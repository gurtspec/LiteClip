# Contributing to LiteClip

Thanks for wanting to help! LiteClip is meant to stay **small, readable and trustworthy**, so anyone can check
what it does. These few rules keep it that way.

## The rules

1. **No internet code.** LiteClip must never connect anywhere. GitHub refuses to build any change that adds network
   code (`.github/workflows/build.yml`).
2. **No ads, accounts, tracking or "engagement" features.** See "The promise" in the README.
3. **No new dependencies.** Only what ships with Windows (.NET Framework 4.x, WPF, Windows APIs) plus the FFmpeg program.
   No NuGet packages, no bundled DLLs.
4. **Builds with Windows' own compiler.** `build.ps1` uses `csc.exe` from .NET Framework, which understands **C# 5**.
   That means no `$"..."` strings, no `?.`, no `nameof`, no `=>` property bodies, no `{ get; } = value`. Plain C# only.
5. **Keep it light.** LiteClip should stay under ~5 MB of RAM in the tray. Don't keep windows, images or timers alive
   while no window is open.
6. **Keep it readable.** Short functions, clear names, a comment where something isn't obvious (especially Windows
   or FFmpeg quirks: write down *why*).
7. **Every text can be translated.** Put user-facing text in code inside `L.T("...")` (with `{0}` for values:
   `L.T("Saved {0}", name)`). Text in `.xaml` files is translated automatically. `build.ps1` regenerates
   `lang/template.txt` from both.
8. **Settings are plain text.** New options go in `Settings.cs` (field + Load + Save, with a comment line in the file),
   in the Settings screen, and in the README's "Customize everything" tables.

## How the code fits together

```
Program.cs        Entry point. Single instance, command line (--save, --pause, --mute-mic ...) via a local named pipe.
                  App class: tray, shortcuts, saving clips, status file, mic mute, memory trimming, restart, uninstall.
Recorder.cs       Starts FFmpeg: screen capture (ddagrab) + audio pipes -> 2-second pieces in the buffer folder.
                  SaveClip() glues the newest pieces into an .mp4 (no re-encoding), names it, runs clean-up.
                  FitToSize() makes the "Fit for Discord" copy.
AudioLoopback.cs  WASAPI capture: "what you hear" (loopback) or a microphone. Writes raw samples to a pipe
                  that FFmpeg reads (silence while muted). Also lists audio devices.
Ui.cs             MainWindow, LibraryView (thumbnail grid), EditorView (preview + trim), SettingsView,
                  Timeline control, Toast pop-up, Tray icon, small dialogs.
Native.cs         Global hotkeys, job object (FFmpeg closes with LiteClip), Recycle Bin, Startup shortcut, memory trim.
Settings.cs       All options with defaults, load/save of settings.ini. Paths: every folder LiteClip uses (portable mode).
Lang.cs           Loads lang\<Language>.txt and translates texts.
ui/*.xaml         Layout and theme (loaded at runtime from embedded resources).
lang/             Translations. template.txt is generated by build.ps1.
build.ps1         Compiles LiteClip, makes lang/template.txt, downloads + verifies FFmpeg.
package.ps1       Makes the release zip and its fingerprints.
.github/          GitHub Actions build (public, with attestations), issue and pull request templates.
```

### Things that look odd but are on purpose

- **Audio goes through named pipes, not FFmpeg's stdin.** .NET writes text-encoding bytes (a BOM) to stdin, which
  scrambles raw audio.
- **No `-use_wallclock_as_timestamps` on audio.** It stamps audio with real-world time while video starts at 0,
  so FFmpeg never writes the audio.
- **AV1 uses Matroska buffer pieces** (with `-reset_timestamps 1`); H.264/HEVC use MPEG-TS. MPEG-TS can't hold AV1,
  and Matroska pieces must restart their clocks for the concat step to keep every frame.
- **Native resolution on NVIDIA stays on the GPU** (zero-copy). Lower resolutions copy frames to memory to scale them.
- **`-surfaces N -delay 0` on NVENC.** FFmpeg's default keeps 4 frames in flight (~11 MB each at 1440p). 2 is plenty
  for a replay buffer; the user can pick 1–4 (`GpuFrames`).
- **Memory trimming.** When no window is open, LiteClip runs the garbage collector and asks Windows to page out
  what it isn't using (`SetProcessWorkingSetSize`). That's why it sits at a few MB in the tray.
- **Uninstall leaves `LiteClip.exe`.** A running program can't delete itself, and the usual "self-delete" tricks look
  like malware to antivirus software. So LiteClip deletes everything else and tells you to delete the exe.

## Building and testing

```powershell
powershell -ExecutionPolicy Bypass -File .\build.ps1
.\dist\LiteClip.exe
powershell -ExecutionPolicy Bypass -File .\package.ps1     # optional: the release zip
```

Before sending a change, please check:

- it builds with `build.ps1`,
- a saved clip plays and has sound: `.\dist\tools\ffprobe.exe -v error -count_frames -show_entries stream=codec_name,nb_read_frames "clip.mp4"`
  (frame count ≈ fps × seconds),
- LiteClip's memory in Task Manager drops back to a few MB a few seconds after closing its window,
- new texts show up in `lang/template.txt`.

## Releasing (maintainers)

1. Update `Version` in `src/Program.cs` and add a section to `CHANGELOG.md`.
2. Push a tag: `git tag v1.2` then `git push origin v1.2`.
3. GitHub Actions builds, packages, attests and publishes the release. Nothing is uploaded from a personal PC.

If the FFmpeg download in `build.ps1` stops working (BtbN moves to a new FFmpeg version), update the zip name there.

## Ideas welcome

Open an issue for bugs or ideas. Good first contributions: testing on AMD/Intel graphics, translations,
multi-monitor improvements, more editor features (cropping, speed, export as GIF).
